# Creative Freedom V2 — design intent

Use for **new website builds, new pages, visual design requests and explicitly
requested redesigns**. Do not launch a visual audit or browser, and do not
change a site's appearance during unrelated bug fixes.

1. **Identify intent:** new site = broad creative freedom; new page = respect
   established brand with a fresh page composition; routine edit = preserve
   current design; explicit redesign = redesign requested scope freely.
2. **Understand context:** use supplied brand, audience, goals, content and
   existing theme first. Never invent brand requirements or overwrite a clear
   user preference. Ask only when a missing decision is genuinely blocking.
3. **Choose one direction:** briefly weigh two or three distinct design
   approaches internally; choose one suitable direction and build it. Do **not**
   generate several complete alternatives unless requested.
4. **Default creativity:** **expressive** on new sites, **brand-consistent**
   on new pages, **conservative** on routine edits. Honor a user-requested
   balanced or experimental direction.
5. **Avoid generic defaults:** don't reflexively use centered gradient hero,
   three identical cards, repetitive icons, or arbitrary decorations.
   Use purposeful typography, asymmetric composition, image treatment,
   rhythm and storytelling where they suit the business. Keep navigation
   familiar and comprehensible.
6. **Preserve quality:** responsive mobile compositions, semantic HTML,
   accessible contrast/focus, reduced-motion preferences, readable content,
   sensible performance and meaningful CTAs. Animations must have purpose.
7. **Design is not constrained by minimal diffs** for an explicitly requested
   new design/redesign. Modify the files necessary for quality, but avoid
   unrelated rewrites, excess dependencies and unnecessary full-project scans.
8. **Honor project conventions:** Tailwind utility classes ONLY, no custom
   CSS, inline styles, or `@apply`; PHP architecture, naming rules, SEO, and
   security remain mandatory. Do not create visual QA/testing commands.
9. **Finish concisely:** state chosen design direction and files changed;
   use scoped verification when available. No automatic SEO/test/design audit.

Read `references/creative-design-guidance.md` **only for a substantial new
site, page composition, or redesign**. Routine edits must not preload it.
