# Quality-first development efficiency

Quality-first policy: efficiency is a preference, never a quality or scope cap. Expand source inspection, load additional applicable references, revisit earlier decisions, rewrite necessary code, and choose batch sizes as needed for correctness, completeness and maintainability. Perform relevant authorized, non-destructive verification; separate report commands remain manual-only. Creative design has no artificial exploration, variant, complexity, batch or token budget. Preserve user scope, branding requirements, strict Tailwind-only styling, PHP conventions, security, accessibility and permissions. Do not bypass platform limits or require external tools. Explicit standard/deep/full/visibility audit modes remain distinct; disclose incomplete coverage and never treat unverified checks as passing.

- Empty project: skip pointless Graphify indexing until meaningful source exists.
- Existing site: start with relevant source and graph context; widen as necessary.
- Tailwind migration: preserve required appearance and behavior; choose batches
  according to dependencies, not a fixed single-page or component limit.
- Large refactor: plan dependency boundaries, track progress, revisit affected
  work when needed, and use necessary rewrites rather than forced minimal diffs.
- Design: use unrestricted creative guidance, with no usage-saving caps.
- Verification: run relevant permitted syntax, build and functional checks in
  safe environments; broaden when necessary. Never touch production data or
  bypass permissions. Dedicated report commands remain explicit and read-only.
- Graphify: reuse valid graphs, confirm with source and refresh when necessary
  and authorized. Prefer incremental sync when supported, not at the expense
  of accuracy. No unnecessary watchers or rebuilds.
- Report useful results, checks, blockers and remaining scope; do not hide detail
  to save tokens. No claim of guaranteed usage reduction.
